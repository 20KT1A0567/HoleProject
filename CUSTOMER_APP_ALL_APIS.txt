SECTION 1 — AUTHENTICATION  (No JWT required)
================================================================================

---
1.1  CHECK IF PHONE IS ALREADY REGISTERED
---
GET https://api.anushatechnologies.com/api/auth/check-phone/{phoneNumber}

Call this BEFORE triggering Firebase OTP to decide Login vs Sign-Up screen.

Postman example:
  Method  : GET
  URL     : https://api.anushatechnologies.com/api/auth/check-phone/+919876543210
  Headers : (none)

Success Response (200):
{
  "exists": true          // true → show Login screen
}                         // false → show Sign-Up screen


---
1.2  SIGN UP (New Customer)
---
POST https://api.anushatechnologies.com/api/auth/signup

Flow: User completes Firebase Phone OTP on device → get Firebase ID token → call this.

Postman example:
  Method  : POST
  URL     : https://api.anushatechnologies.com/api/auth/signup
  Headers : Content-Type: application/json
  Body (raw JSON):
{
  "firebaseIdToken": "eyJhbGciOiJSUzI1NiIsImtpZCI6...",
  "name": "Ramesh Kumar",
  "email": "ramesh@example.com",
  "fcmToken": "fMEuXxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
}

Fields:
  firebaseIdToken  (required) - Firebase ID token after phone OTP verified
  name             (optional) - Customer display name
  email            (optional) - Customer email
  fcmToken         (optional) - Firebase Cloud Messaging token for push notifications

Success Response (200):
{
  "accessToken": "eyJhbGciOiJIUzI1NiJ9...",
  "jwtToken": "eyJhbGciOiJIUzI1NiJ9...",
  "refreshToken": "abc123refreshtoken",
  "expiresIn": 86400,
  "customerId": 101,
  "phoneNumber": "+919876543210",
  "name": "Ramesh Kumar",
  "email": "ramesh@example.com",
  "roles": "CUSTOMER"
}

Error (409 Conflict) — phone already registered:
{
  "error": "Account already exists. Please login."
}

Error (401) — invalid Firebase token:
{
  "error": "Invalid or expired Firebase token"
}

3.2  ADD NEW ADDRESS  ← latitude & longitude MANDATORY
---
POST https://api.anushatechnologies.com/api/addresses

Postman example:
  Method  : POST
  URL     : https://api.anushatechnologies.com/api/addresses
  Headers :
    Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
    Content-Type: application/json
  Body (raw JSON):
{
  "addressType": "home",
  "flatNumber": "Flat 3B",
  "addressLine1": "Srinivasa Apartments",
  "addressLine2": "Kukatpally Housing Board Colony",
  "landmark": "Near KPHB Metro Station",
  "city": "Hyderabad",
  "state": "Telangana",
  "postalCode": "500072",
  "latitude": 17.494718,
  "longitude": 78.399614,
  "isDefault": true
}

Fields:
  addressType    (required) - "home" | "work" | "other"
  flatNumber     (optional) - Flat/door/unit number, e.g. "Flat 3B"
  addressLine1   (required) - Building/house name or primary street address
  addressLine2   (optional) - Area/locality/colony
  landmark       (optional) - Nearby landmark for easy finding
  city           (required) - City name
  state          (optional) - State name
  postalCode     (required) - 6-digit PIN code
  latitude       (MANDATORY) - GPS latitude from device location picker
  longitude      (MANDATORY) - GPS longitude from device location picker
  isDefault      (required) - true to make this the default delivery address

NOTE: If isDefault is true, the previous default address is automatically
      cleared. Only one address can be default at a time.

Success Response (200):
{
  "id": 7,
  "addressType": "home",
  "flatNumber": "Flat 3B",
  "addressLine1": "Srinivasa Apartments",
  "addressLine2": "Kukatpally Housing Board Colony",
  "landmark": "Near KPHB Metro Station",
  "city": "Hyderabad",
  "state": "Telangana",
  "postalCode": "500072",
  "latitude": 17.494718,
  "longitude": 78.399614,
  "isDefault": true
}

================================================================================
IMPORTANT NOTES FOR FRONTEND TEAM
================================================================================

1. JWT TOKEN USAGE
   - After login/signup, store both accessToken and refreshToken
   - accessToken goes in every protected request as:
       Authorization: Bearer <accessToken>
   - When you get 401, call POST /api/auth/refresh with refreshToken
   - On logout, call POST /api/auth/logout to invalidate refreshToken

2. ADDRESS — LATITUDE & LONGITUDE ARE MANDATORY
   - Every address POST and PUT MUST include latitude and longitude
   - Obtain these from the device GPS / Google Maps place picker
   - Without coordinates, delivery routing and rider assignment will fail
   - Example: "latitude": 17.494718, "longitude": 78.399614

3. PAYMENT FLOW (ONLINE)
   a) POST /api/orders { paymentMethod: "ONLINE", addressId, couponCode }
      → receive orderId and orderNumber
   b) POST /api/payment/initiate { orderId }
      → receive razorpayOrderId, amount (paise), keyId
   c) Open Razorpay SDK checkout with these details
   d) On Razorpay success callback, call:
      POST /api/payment/verify { razorpayOrderId, razorpayPaymentId,
                                  razorpaySignature, receipt }

4. CART — USE variantId, NOT productId
   - Products have variants (e.g. 500g, 1kg, 250ml)
   - When adding to cart send variantId from product.variants[i].id
   - Not productId

5. SEARCH FLOW (Zepto-style)
   - User types → call /api/products/suggestions?q=&limit=10 for instant hints
   - User presses search → call /api/products/search/paginated?q=&page=0&size=20

6. LIVE TRACKING — FIREBASE RTDB (preferred over REST)
   - Listen to Firebase RTDB path: tracking/{orderNumber}
   - This gives real-time location updates without polling
   - Use GET /api/tracking/{orderNumber} only as a fallback

7. FCM TOKEN
   - On every app launch: call POST /api/save-token with phone + fcmToken
   - This ensures push notifications reach the right device
